# بروتوكول الاتصال المحلي — المسودة الأولى

## النقل

- WebSocket فوق TCP لاتصال اللعب.
- UDP Broadcast لاكتشاف المضيف داخل الشبكة المحلية.
- عنوان افتراضي مقترح لخدمة WebSocket: `0.0.0.0:40405`.
- منفذ اكتشاف UDP: `40406`.
- مسار WebSocket: `/ws`.

## اكتشاف المضيف

يرسل العميل رسالة UDP نصية `DOMINO_DISCOVER_V1` إلى عنوان البث المحلي والمنفذ `40406`. يرد المضيف برسالة JSON تتضمن اسم الغرفة، إصدار البروتوكول، والمنفذ. عنوان IP المصدر للرد هو عنوان المضيف الذي يحاول العميل الاتصال به.

يجب ألا يكون الاكتشاف التلقائي هو الطريقة الوحيدة؛ فقد تمنع بعض نقاط الاتصال بث UDP أو تعزل الأجهزة. لذلك يجب توفير إدخال IP يدوياً ورمز QR لاحقاً.

## شكل الرسائل

كل رسالة WebSocket كائن JSON يتضمن:

- `v`: إصدار البروتوكول.
- `type`: نوع الرسالة.
- `requestId`: معرّف فريد للطلب عند الحاجة لمنع تكرار التنفيذ.
- `payload`: بيانات الرسالة.

رسائل العميل المقترحة:
- `join_room`
- `reconnect`
- `play_tile`
- `pass_turn`
- `ping`

رسائل المضيف المقترحة:
- `join_accepted`
- `join_rejected`
- `room_snapshot`
- `turn_changed`
- `move_accepted`
- `move_rejected`
- `player_disconnected`
- `player_reconnected`
- `round_finished`
- `pong`

## قواعد الثقة

- لا يرسل العميل حالة يطلب من المضيف اعتمادها كما هي.
- لا يقبل المضيف معرف لاعب من الرسالة دون ربطه باتصال موثوق في الجلسة.
- يتحقق المضيف من الدور وملكية الحجر ومطابقة الطرف وحالة الجولة.
- لا تُبث بيانات اليد الخاصة للاعب إلى بقية اللاعبين.
- يجب أن تكون كل حركة قابلة لكشف التكرار بواسطة `requestId`.

## مخاطر يجب اختبارها

- عزل العملاء (Client Isolation) في نقاط الاتصال.
- اختلاف نطاق العناوين بين الشركات والأجهزة.
- حظر بث UDP.
- انتقال نقطة الاتصال إلى وضع توفير الطاقة.
- تغير عنوان IP عند إعادة الاتصال.
- تعليق التطبيق في الخلفية أو إيقافه بواسطة النظام.
