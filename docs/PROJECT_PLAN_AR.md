# وثيقة تخطيط المشروع — دومينو الشبكة

**اسم المشروع:** دومينو الشبكة (Domino LAN)  
**الإصدار:** 0.1.0 — وثيقة تأسيسية  
**المنصة:** Android  
**التقنية:** Flutter / Dart  
**الحالة:** التخطيط مع بدء التأسيس البرمجي

## 1. الهدف

إنشاء لعبة دومينو لأربعة أشخاص، يستخدم كل شخص هاتف Android مستقلاً. تتصل الأجهزة جميعاً بنقطة اتصال واحدة أو شبكة Wi-Fi محلية. لا يتطلب اللعب اتصالاً بالإنترنت أو حسابات أو خادماً سحابياً.

## 2. المواصفات المعتمدة

| العنصر | القرار |
|---|---|
| عدد اللاعبين | 4 |
| الفرق | فريقان؛ اللاعبان 1 و3 معاً، واللاعبان 2 و4 معاً |
| الأحجار | Double-Six؛ عددها 28 |
| التوزيع | 7 أحجار لكل لاعب |
| كومة السحب | لا توجد في مباراة الأربعة لاعبين بهذه المجموعة |
| الشبكة | Hotspot أو Wi-Fi محلية |
| المضيف | هاتف أحد اللاعبين ويكون مرجع حالة المباراة |
| الحسابات | لا توجد حسابات أو تسجيل دخول |
| الواجهة | عربية RTL |
| الناتج | APK قابل للتثبيت |

## 3. الأدوار والمسؤوليات

### هاتف المضيف
- إنشاء الغرفة وإعلانها داخل الشبكة المحلية.
- قبول ثلاثة لاعبين إضافيين فقط.
- إنشاء المجموعة وخلطها وتوزيعها.
- إدارة الدور والتحقق من كل حركة.
- حفظ الحالة الكاملة ونتيجة الجولة.
- إرسال حالة مخصصة لكل لاعب، مع عدم كشف أحجار اللاعبين الآخرين.

### هاتف اللاعب
- اكتشاف الغرفة أو الاتصال بعنوان المضيف يدوياً.
- إرسال طلب الانضمام والاسم.
- عرض أحجار اللاعب فقط والحالة العامة للطاولة.
- إرسال اختيار الحجر والطرف المطلوب.
- استقبال تأكيد المضيف وتحديث واجهة اللعب.

## 4. توزيع المقاعد والفرق

| المقعد | الفريق | الموقع المقترح |
|---|---|---|
| 1 | A | أسفل الشاشة لدى اللاعب المحلي |
| 2 | B | يمين الشاشة |
| 3 | A | أعلى الشاشة |
| 4 | B | يسار الشاشة |

يجب أن يكون الشريكان في مقعدين متقابلين.

## 5. قواعد المجموعة والتوزيع

- إنشاء كل التركيبات الممكنة للأرقام من 0 إلى 6 دون تكرار؛ المجموع 28 حجراً.
- خلط عشوائي باستخدام مولّد عشوائي مناسب.
- إعطاء 7 أحجار لكل مقعد.
- لا توجد أحجار متبقية للسحب.
- ترتيب الأحجار في يد اللاعب للعرض فقط، ولا يغير ملكيتها أو قيمتها.

## 6. القواعد التشغيلية الأولية

هذه قواعد افتراضية قابلة للتعديل بعد تثبيت قواعد اللعب المحلية المطلوبة:

1. في الجولة الأولى يبدأ صاحب أعلى مزدوج، أي 6-6. يحمل كل حجر هوية فريدة في المحرك.
2. يوضع حجر البداية أولاً، ثم يتناوب اللعب باتجاه عقارب الساعة.
3. يجب مطابقة أحد طرفي الحجر مع أحد طرفي السلسلة المفتوحين.
4. يختار اللاعب وضع الحجر على الطرف الأيسر أو الأيمن، ويقوم المحرك بتوجيهه تلقائياً.
5. لا يسمح بالتمرير إذا كان لدى اللاعب أي حجر صالح للعب.
6. لا توجد عملية سحب؛ عند عدم وجود حركة صالحة يمرر اللاعب دوره.
7. عند مرور اللاعبين الأربعة المتتاليين تنتهي الجولة بانسداد.
8. تنتهي الجولة أيضاً عندما ينفد مخزون لاعب واحد من الأحجار.

## 7. نظام النقاط — إعداد مبدئي

- عند خروج لاعب من أحجاره، يفوز فريقه بالجولة.
- عند الانسداد، يفوز الفريق الأقل مجموعاً للنقاط المتبقية في يديه.
- يمنح الفريق الفائز نقاط أحجار الفريق المنافس المتبقية وفق النموذج الأولي.
- هدف المباراة الافتراضي المقترح 100 نقطة.

**تنبيه:** طريقة احتساب نقاط الشريك والفارق عند الانسداد، وهدف المباراة، وقاعدة بداية الجولات التالية تحتاج اعتماداً نهائياً قبل تثبيت إصدار القواعد. ستبقى قابلة للضبط في المحرك بدلاً من دفنها في واجهة العرض.

## 8. الاتصال المحلي

- خادم WebSocket يعمل على هاتف المضيف ويرتبط بواجهات الشبكة المحلية.
- اكتشاف UDP Broadcast كطريقة تلقائية أولية.
- اتصال بديل بإدخال عنوان IP ورقم المنفذ يدوياً.
- رمز غرفة/انضمام لمنع دخول أجهزة غير مقصودة.
- رسائل JSON ذات نوع وإصدار ومعرّف طلب.
- المضيف وحده يقبل أو يرفض الحركة ويصدر تحديث الحالة.
- عند انقطاع لاعب، تتوقف المباراة مؤقتاً حتى عودته أو قرار المضيف.
- عند خروج المضيف أو توقفه، تتوقف المباراة في النسخة الأولى؛ لا يوجد نقل تلقائي للاستضافة.

## 9. الشاشات

1. الشاشة الرئيسية: إنشاء غرفة، الانضمام، الإعدادات، التعليمات.
2. إنشاء غرفة: الاسم، رمز الغرفة، عدد المقاعد، إعدادات المباراة.
3. البحث عن غرفة: قائمة الغرف المكتشفة، وإدخال IP يدوياً.
4. غرفة الانتظار: أربعة مقاعد، أسماء، فرق، حالة الاتصال، بدء المباراة.
5. طاولة اللعب: السلسلة، أطرافها، اللاعبين، عدد الأحجار، اليد الخاصة، الدور الحالي، النقاط.
6. نهاية الجولة: سبب النهاية، الفائز، نقاط الجولة.
7. نهاية المباراة: الفريق الفائز وإعادة اللعب.
8. الإعدادات: الاسم والصوت والاهتزاز وهدف النقاط.

## 10. المتطلبات غير الوظيفية

- عدم الحاجة للإنترنت بعد تثبيت APK.
- استجابة سريعة للحركات على الشبكة المحلية.
- عدم تسريب أحجار اللاعب إلى أجهزة أخرى.
- التحقق من صحة الحركة مركزياً عند المضيف.
- استعادة الجلسة بعد انقطاع مؤقت للاعب قدر الإمكان.
- دعم اتجاه RTL ومقاسات الشاشات المختلفة.
- منع ازدواج تنفيذ الحركة عند إعادة إرسال الرسالة.

## 11. خارج نطاق النسخة الأولى

اللعب عبر الإنترنت، الذكاء الاصطناعي، الدردشة، الحسابات، البطولات، المتجر، الإعلانات، ونقل الاستضافة تلقائياً.

## 12. مراحل التنفيذ

1. تجهيز Flutter وبناء نسخة Android فارغة.
2. محرك الأحجار والقواعد واختباراته.
3. إثبات اتصال هاتفين على Hotspot.
4. إضافة اكتشاف المضيف والانضمام ورمز الغرفة.
5. توسيع الاختبار إلى أربعة هواتف.
6. بناء غرفة الانتظار وتوزيع الفرق.
7. توصيل واجهة المباراة بمحرك القواعد.
8. إدارة الانقطاع والنتائج وإعادة المباراة.
9. اختبار APK وإصدار نسخة موقعة.

## 13. معايير قبول النسخة الأولى

- انضمام أربعة هواتف إلى غرفة واحدة دون إنترنت.
- لا يسمح بمقعد خامس.
- توزيع 7 أحجار لكل لاعب دون تكرار أو فقد.
- لا يرى اللاعب سوى أحجاره الخاصة.
- كل حركة صحيحة تظهر بالترتيب نفسه في الأجهزة الأربعة.
- يرفض المضيف الدور الخاطئ والحجر غير المملوك والحركة غير المطابقة.
- تنتج نهاية الجولة والنقاط نفسها على جميع الأجهزة.
- يمكن للاعب إعادة الاتصال واستعادة جلسته بعد انقطاع مؤقت.
- يمكن إعادة المباراة داخل الغرفة نفسها.
