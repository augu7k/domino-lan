# دومينو الشبكة — Domino LAN

لعبة دومينو جماعية لأربعة لاعبين على Android وiPhone، ضمن شبكة Wi-Fi محلية أو نقطة اتصال Hotspot، دون اشتراط اتصال بالإنترنت.

## المواصفات المعتمدة

- أربعة لاعبين حقيقيين، فريقان، كل فريق لاعبان متقابلان.
- مجموعة Double-Six تتكون من 28 حجراً.
- 7 أحجار لكل لاعب، ولا توجد كومة سحب في هذا التوزيع.
- هاتف المضيف يدير حالة المباراة ويتحقق من الحركات.
- اتصال محلي عبر WebSocket، مع اكتشاف UDP وخيار إدخال عنوان المضيف يدوياً.
- دعم Android وiOS من قاعدة Flutter واحدة.
- الواجهة باللغة العربية واتجاه RTL.

## تطبيق الويب (PWA)\n\nأضيفت واجهة ويب تأسيسية في مجلد `web/` مع manifest وService Worker. هذه الواجهة قابلة للتثبيت بعد استضافتها عبر HTTPS، لكنها لا تتضمن بعد خادم غرف أو لعباً جماعياً. راجع [خطة معمارية الويب](docs/WEB_ARCHITECTURE_AR.md) لمعرفة مراحل تحويل الاتصال.\n\n## حالة المشروع

هذه نسخة تأسيسية (0.1.0). يجري تطوير واجهة اللعب وطبقة الاتصال والاستعادة تدريجياً. نجاح البناء الآلي لا يعني اكتمال اختبار الاتصال على أجهزة حقيقية.

## متطلبات التطوير

- Flutter SDK حديث متوافق مع Dart 3.4 أو أحدث.
- Android SDK لبناء Android.
- جهاز Mac مع Xcode لبناء iOS محلياً أو إصدار نسخة iPhone موقعة.
- أربعة هواتف فعلية لاختبار اللعب الجماعي.

## إعداد Android

من داخل مجلد المشروع:

```bash
flutter create --platforms=android --org com.domino.lan .
flutter pub get
flutter test
flutter run
```

بناء APK تجريبي:

```bash
flutter build apk --debug
```

## إعداد iOS

يتطلب بناء تطبيق iPhone جهاز Mac مثبتاً عليه Xcode:

```bash
flutter create --platforms=ios --org com.domino.lan .
flutter pub get
flutter build ios --simulator --debug
```

قبل تشغيل التطبيق على iPhone، يجب أن يحتوي `ios/Runner/Info.plist` على المفتاح `NSLocalNetworkUsageDescription` مع وصف واضح لاستخدام الشبكة المحلية. يضيف فحص GitHub Actions هذا الوصف تلقائياً عند إنشاء منصة iOS.

لبناء نسخة قابلة للتثبيت والتوزيع على أجهزة iPhone يلزم إعداد توقيع Apple عبر Xcode وحساب Apple Developer مناسب؛ بناء المحاكي في CI ليس ملف IPA جاهزاً للتوزيع.

## الاتصال المحلي بين النظامين

- يمكن أن يكون المضيف Android أو iPhone، وينضم إليه مستخدمو النظام الآخر.
- يجب السماح للتطبيق باستخدام Local Network عند ظهور طلب iOS.
- يجب أن تكون الأجهزة على الشبكة المحلية نفسها.
- قد يمنع بعض موجّهات Wi-Fi أو أوضاع Hotspot اكتشاف UDP؛ عندها استخدم عنوان IP للمضيف ورمز الغرفة يدوياً من شاشة الانضمام.
- لا يتطلب اللعب خادماً على الإنترنت.

## فحوص GitHub Actions

يتضمن سير العمل فحص Dart والاختبارات وبناء APK تجريبي، إضافة إلى بناء تطبيق iOS للمحاكي على macOS. بناء المحاكي يتحقق من التوافق البرمجي ولا يغني عن اختبار iPhone فعلي أو إعداد توقيع الإصدار.

## الخصوصية والأمان

لا يتطلب التطبيق حساباً أو خادماً خارجياً. رسائل اللعب تمر داخل الشبكة المحلية. يجب عدم إرسال أحجار اللاعبين الخاصة إلى أجهزة الخصوم؛ المضيف يحتفظ بالحالة الكاملة ويرسل لكل لاعب البيانات المسموح بها فقط.
